## Запуск на новом ПК

```powershell
git clone https://github.com/AlexPlutsak/Careerbot.git
cd Careerbot\Career-Bot-0.19.1
start-career-bot-app.cmd
```

Нужны Python и Ollama. Для локальной модели запустить `setup-ollama.cmd`; он устанавливает `qwen3:8b`. Затем в Edge загрузить распакованное расширение из `Career-Bot-0.19.1/hh-career-bot-extension` через `edge://extensions` → режим разработчика → «Загрузить распакованное».

Версии кода на момент передачи:

- сервер: `0.21.7`;
- расширение Edge: `2.3.8`.

После изменения расширения всегда требуется его перезагрузка в `edge://extensions` и обновление вкладок hh.ru.

## Что умеет приложение

- собирает и сохраняет вакансии hh.ru;
- получает полное описание через API/расширение, если карточка была короткой;
- считает пригодность вакансии и объясняет оценку;
- генерирует русские сопроводительные локальной Ollama;
- хранит письма, подтверждение пользователя и статусы воронки;
- поддерживает пакетную генерацию и прогресс;
- импортирует профиль/резюме с hh.ru через расширение;
- ведёт диагностику интерфейса HH без отправки откликов.

## Ключевая цель

Нужно прийти к автоотправке только заранее одобренных писем по простым вакансиям HH. Целевой пользовательский сценарий: подготовить много вакансий и писем, подтвердить партию, затем получить результат без ручного открытия каждой карточки.

## Текущее состояние автоотправки

Массовая автоотправка **намеренно отключена** в сервере, UI и расширении.

Причина: в ранней версии пользователь получил 10 откликов без сопроводительных писем. Старый алгоритм кликал «Откликнуться», не находил поле, помечал часть вакансий как ручные и переходил дальше. Нельзя включать его обратно одним удалением блокировок.

Одиночная кнопка «Подготовить отклик на hh.ru» может открыть вакансию и пытаться вставить письмо, но этот режим ещё не доказан на реальном интерфейсе. Он не является готовой автоматизацией.

## Какие сценарии HH нужно обработать

1. После «Откликнуться» сразу открывается форма с сопроводительным письмом.
2. Отклик уже создан, ниже появляется «Приложить сопроводительное письмо».
3. Письмо нужно отправить в чате конкретной вакансии.
4. Вопросы робота-рекрутера, тесты, анкеты, обязательные выборы — пока `needs_manual`; бот не отвечает за пользователя.

Нужно отдельно хранить: создание отклика, открытие формы, успешную вставку текста, нажатие финальной кнопки и подтверждение отправки. Если результат после нажатия неизвестен, повторно не отправлять.

## Что уже сделано в диагностике

Кнопка «Диагностика без отправки» создаёт 15-минутную сессию и открывает HH с hash `careerBotDiagnostic`. Она не нажимает кнопки сайта и не отправляет отклик.

Диагностика сохраняет:

- видимые поля, включая `textarea`, `contenteditable`, `role=textbox` и элементы в открытых Shadow DOM;
- технические идентификаторы `data-qa`, названия, доступность и read-only-состояние;
- релевантные кнопки;
- признаки анкеты, вопроса или теста;
- маршрут и этап в таблице `apply_sessions`.

Добавленные этапы: `queued`, `opening`, `application_created`, `letter_form_open`, `letter_inserted`, `sending`, `sent_confirmed`, `needs_manual`, `unknown_result`, `diagnostic`.

Известные элементы HH:

- `vacancy-response-popup-form-letter-input` — поле сопроводительного в одной из форм;
- `responded-success-attach-cover-letter` — «Приложить сопроводительное письмо»;
- `vacancy-response-link-view-topic` — чат отклика;
- `vacancyResponses-button` и `chatikActivator-button` — общие элементы страницы, их нельзя считать чатами конкретной вакансии.

## Последняя найденная проблема и исправление

На обычной странице вакансии диагностический отчёт показывал `fieldCount: 0`. Это нормально: форма ещё не открыта, а диагностика сама не кликает «Откликнуться».

При этом старая версия ошибочно считала текст вакансии, фильтры и общие формы страницы «обязательным вопросом». Это исправлено в расширении 2.3.8 и сервере 0.21.7: без открытого текстового поля такой экран должен стать `unknown`, а не `manual`.

После обновления нужно проверять уже отправленную вакансию: вручную нажать «Приложить сопроводительное письмо», дождаться формы, затем в панели диагностики выбрать «Записать поля и кнопки». Ничего не отправлять. Для чата нужен аналогичный снимок открытого чата без вопросов.

## Следующие шаги разработки

1. Собрать свежие отчёты для трёх реальных веток HH после обновления 2.3.8.
2. На их основе реализовать адаптер HH как конечный автомат, а не как цепочку общих селекторов.
3. Для каждой ветки сначала проверить только открытие формы и вставку письма с визуальным подтверждением.
4. Добавить финальное нажатие и подтверждение результата для одной новой, заранее одобренной вакансии.
5. Проверить одну вакансию каждого типа, затем партии 3 → 10 → 40.

Критерий готовности: ни одного отклика без письма, ни одного двойного отклика, вакансии с вопросами всегда останавливаются до отправки.

## Качество писем и скоринг: известные долги

- Скоринг всё ещё частично основан на словарях. Он может неверно трактовать `5/2`, релокацию и другие условия без контекста.
- Разбор опыта зависит от оформления текста: блоки опыта сейчас распознаются по датам и маркерам списка. При изменении резюме качество подбора фактов может меняться.
- Проверка новых чисел и инструментов недостаточно строга: требования вакансии не должны становиться «опытом кандидата».
- До смены модели стоит стабилизировать библиотеку фактов: источник → тип опыта → личное действие → результат → ограничение формулировки.

Правила для писем: русский язык, мужской род, без плейсхолдеров, двойных подписей и канцелярита. Хакатоны и кейсы нельзя представлять коммерческой работой. Oasis — коммерческий логистический опыт; Solutions — самостоятельное исследование; X5/Ростелеком/Alfa/Калининград — учебные кейсы и хакатоны.
