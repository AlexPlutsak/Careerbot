# AI-сопроводительные письма

## Цель

Письмо должно выглядеть написанным под конкретную вакансию, но каждое утверждение о кандидате обязано подтверждаться карьерным профилем или резюме. Модель не добавляет компании, стаж, инструменты, метрики и достижения от себя.

## Конвейер

1. Разобрать вакансию на название роли, задачи, обязательные требования и желательные навыки.
2. Разобрать профиль и резюме на атомарные факты: роль, действие, инструмент, результат, отрасль и период.
3. Сопоставить каждому требованию до трех подтвержденных фактов кандидата.
4. Передать модели только вакансию, найденные пары и настройки тона.
5. Проверить черновик: сопоставить утверждения с исходными фактами и отметить уверенность проверки.
6. Показать письмо пользователю в Safe Mode для редактирования и ручного подтверждения.

## Структура данных

Факт кандидата:

```json
{
  "id": "fact-17",
  "source": "resume",
  "kind": "tool",
  "text": "Использовала Jira для управления задачами",
  "approved": true
}
```

Связка с требованием:

```json
{
  "requirement": "Координация продуктовых проектов",
  "fact_ids": ["fact-17", "fact-23"],
  "confidence": 0.86
}
```

## Правила текста

- 90-150 слов, приветствие, два содержательных абзаца и короткое завершение.
- Указать точное название вакансии и компанию, если компания известна.
- Выбрать 2-4 наиболее сильные связки `требование → факт → польза`.
- В каждом содержательном абзаце сначала назвать подтвержденное действие или опыт, затем объяснить его пользу для задачи работодателя.
- Упоминать не более трех инструментов и только при прямом соответствии требованиям вакансии.
- Писать связным текстом, без списка навыков через запятую.
- Не повторять один факт разными словами.
- Не утверждать результат или уровень владения, если их нет в источнике.
- При слабом совпадении использовать осторожную формулировку или явно сообщить, что фактов недостаточно.

## Проверка результата

После генерации модель возвращает не только текст, но и карту утверждений:

```json
{
  "letter": "...",
  "claims": [
    {"text": "Работала с Jira", "fact_ids": ["fact-17"]}
  ],
  "unsupported_claims": []
}
```

Career Bot принимает точные цитаты автоматически, помечает близкие переформулировки для просмотра и показывает предупреждение для основания, которое не удалось найти. Полноценный черновик не удаляется из-за одного спорного основания: решение остается за пользователем в Safe Mode. Новые числа и латинские названия, отсутствующие одновременно в профиле и вакансии, выделяются отдельным предупреждением.

## Подключение модели

Модель подключается через интерфейс `LLMAdapter`, чтобы позже можно было выбирать внешний API или локальную модель. Ключ хранится только на компьютере пользователя и никогда не попадает в текст вакансии, журнал запросов или удаленную базу.

## Критерии приемки

- Для вакансии младшего Product Manager письмо связывает продуктовые задачи только с подтвержденными UX-исследованиями, концепциями и инструментами кандидата.
- Для клиентской роли письмо выбирает подтвержденные Excel, PowerPoint, Jira или опыт коммуникации, если они присутствуют в профиле.
- Удаление навыка из профиля исключает его из нового письма.
- Пустой профиль не приводит к выдуманному письму: интерфейс просит добавить факты.
- Пользователь видит, какие фрагменты резюме стали основанием для каждого абзаца.
